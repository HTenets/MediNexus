# MediNexus 前端页面逻辑优化 - Product Requirement Document

## Overview
- **Summary**: 对 MediNexus 前端现有页面进行逻辑梳理和结构优化，修复 Tooltip 显示错位问题，重构个人中心和设置页面的定位，合并系统状态到设置页面，消除功能冗余，建立清晰的页面层级和跳转逻辑。
- **Purpose**: 解决当前页面逻辑混乱、功能冗余、定位不清的问题，使用户能够快速找到所需功能，提升整体使用体验。
- **Target Users**: MediNexus 平台的所有终端用户（患者、医生、管理员）

## Goals
- 修复左侧边栏 Tooltip 悬停效果错位问题
- 重构个人中心页面，聚焦于用户医疗数据与 AI 功能配置
- 重构设置页面，聚焦于账户通用设置与系统偏好
- 合并系统状态页面到设置页面，减少导航层级
- 消除"开始问诊"等功能入口的冗余
- 建立清晰的页面定位和逻辑跳转关系

## Non-Goals (Out of Scope)
- 不修改首页（营销页）的内容和结构
- 不修改问诊流程（consultation、analysis、review、summary）的核心逻辑
- 不修改健康记录和患者管理页面的主要功能
- 不新增后端 API 或数据模型
- 不修改整体设计语言和 UI 组件库

## Background & Context
当前前端已开发了 15+ 个页面，但存在以下问题：
1. 左侧边栏折叠时的 Tooltip 显示错位，菱形箭头与圆角矩形组合效果不佳
2. "开始问诊"功能入口过多（侧边栏、个人中心、健康记录等），存在冗余
3. 个人中心页面定位模糊，混杂了快捷操作、系统设置入口、健康数据等多种内容
4. 设置页面包含了数据管理、设备管理等医疗相关功能，与通用设置定位不符
5. 系统状态作为独立导航项，与整体用户功能关联性不强

用户已明确两个核心页面的定位：
- **个人中心**：用户个人医疗数据中心，包括健康报告、健康记录、设备授权、AI 分析模型、AI 分析强度等功能配置
- **设置页面**：通用系统设置，包括账户信息、通知偏好、语言地区等

## Functional Requirements

### FR-1: 修复 Tooltip 悬停显示
- 删除左侧边栏 Tooltip 的菱形箭头指示器
- 保留圆角矩形提示框，确保文字清晰可读
- 修正 Tooltip 定位，确保不出现错位

### FR-2: 重构个人中心页面
- 保留用户基本信息展示区域
- 保留健康指标概览模块（可优化展示形式）
- 新增 AI 分析配置模块（模型选择、分析强度、诊断偏好等）
- 新增设备授权管理模块（健康数据采集设备列表、授权状态）
- 新增健康报告入口（跳转到健康记录/报告列表）
- 移除"开始问诊"快捷操作（消除冗余）
- 移除功能菜单中的系统设置相关入口（通知设置、隐私安全、系统设置）
- 移除功能菜单中的"患者管理"入口（医生视角功能，保持导航栏入口即可）

### FR-3: 重构设置页面
- 保留账户信息模块
- 保留通知偏好模块
- 保留隐私与安全模块（包含密码修改、双因素认证、登录设备管理）
- 保留语言与地区模块
- 移除"数据管理"模块（健康数据相关应归个人中心）
- 新增"系统状态"模块（从独立页面合并进来）
- 移除顶部的"查看个人中心"跳转按钮（通过导航栏访问即可）

### FR-4: 调整左侧边栏导航
- 移除"系统状态"导航项
- 保留：控制台、AI 问诊、健康记录、患者管理、个人中心、设置
- 调整导航项顺序，使其更符合用户使用习惯

### FR-5: 优化页面跳转逻辑
- 确保个人中心各功能模块跳转到正确页面
- 确保设置页面各模块可正常访问
- 更新所有相关页面的返回/跳转链接
- 确保用户下拉菜单中的链接正确有效

## Non-Functional Requirements

### NFR-1: 视觉一致性
- 所有页面修改需遵循现有设计规范（玻璃态、渐变色、圆角等）
- 保持与现有页面一致的动画效果和交互反馈
- 确保响应式布局在不同屏幕尺寸下正常显示

### NFR-2: 代码质量
- 遵循现有代码风格和组件使用模式
- 保持 TypeScript 类型安全
- 不引入新的第三方依赖

### NFR-3: 可维护性
- 组件结构清晰，职责单一
- 页面布局与现有页面保持一致
- 便于后续功能扩展

## Constraints
- **技术栈**: Next.js 14 (App Router), React 18, TypeScript, TailwindCSS 3, Framer Motion
- **设计规范**: 沿用现有 MediNexus 设计系统
- **时间范围**: 仅修改前端页面逻辑，不涉及后端
- **依赖**: 现有组件库（AppShell, Badge, Card 等）

## Assumptions
- 用户主要以普通患者视角使用，患者管理功能保留给医生/管理员
- 系统状态是偏技术/运维的功能，放在设置中更合适
- AI 分析配置和设备授权是用户级别的医疗功能配置，属于个人中心范畴
- 健康记录页面已有完整功能，个人中心仅提供入口和概览

## Acceptance Criteria

### AC-1: Tooltip 显示修复
- **Given**: 用户在左侧边栏折叠状态下
- **When**: 鼠标悬停在导航项上
- **Then**: 显示圆角矩形 Tooltip 提示文字，无菱形箭头，位置准确不错位
- **Verification**: `human-judgment`

### AC-2: 个人中心页面重构完成
- **Given**: 用户访问 /profile 页面
- **When**: 查看页面内容
- **Then**: 页面包含用户信息、健康数据概览、AI 分析配置、设备授权管理、健康报告入口等医疗相关模块，无系统设置入口和"开始问诊"快捷操作
- **Verification**: `human-judgment`

### AC-3: 设置页面重构完成
- **Given**: 用户访问 /settings 页面
- **When**: 查看页面内容
- **Then**: 页面包含账户信息、通知偏好、隐私与安全、语言与地区、系统状态等通用设置模块，无医疗数据相关模块
- **Verification**: `human-judgment`

### AC-4: 左侧边栏导航调整
- **Given**: 用户登录后查看左侧边栏
- **When**: 浏览导航项
- **Then**: 导航项包含控制台、AI 问诊、健康记录、患者管理、个人中心、设置，共 6 项，无"系统状态"独立导航项
- **Verification**: `programmatic`

### AC-5: 页面跳转逻辑正确
- **Given**: 用户在任意页面
- **When**: 点击导航链接或功能入口
- **Then**: 跳转到正确的目标页面，无死链，跳转逻辑符合页面定位
- **Verification**: `human-judgment`

### AC-6: 项目构建成功
- **Given**: 完成所有修改后
- **When**: 执行 npm run build
- **Then**: 项目构建成功，无 TypeScript 错误，无运行时错误
- **Verification**: `programmatic`
