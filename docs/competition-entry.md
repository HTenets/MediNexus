1. 创意名称 + 创意介绍

想解决什么问题：
基层医疗资源分布不均，大量患者因缺乏医学知识在小病上过度焦虑或在大病上延误就医，而现有的 AI 问诊产品要么封闭收费，要么回答质量不可靠且缺乏审核机制，同时我也认为，平时对健康的关注，也能帮助我们即时发现身体的问题，因此想要制作一个带个人健康管理+综合医疗问诊的Agent。

为什么会想到做这个：
作者所在四线小城市，一些大病往往需要去省会或者发达城市去看病，往往劳民伤财；同时作者作为一个吃程序员，日常的久坐以及熬夜等往往会慢慢损耗自己的身体健康。随着LLM的发展，将医学理论知识+临床案例+前沿论文等数据作为数据库提供给Agent，那么Agent能否成长为一个全能的个人健康管家+日常病症问诊的医疗专家，让我看到了很多的可能性。同时看到开源社区有很多优秀的 LLM 项目，但没有一个真正面向医疗问诊场景、且具备完整 Agent 协作流程的开源方案。我们决定做一个——既能为患者提供参考级医疗建议，又能作为用户个人的健康检测管家，让每个人都能享受到更好的医疗问诊条件。

作者同时是一名研二的在校生，想要自己独立完成一个Agent项目，边学边做，整个项目在github开源，记录自己对整个项目开发过程的思考和总结，不断提升对LLM和Agent框架的理解，打牢基础，为秋招做准备。

大概是什么产品：
一个开源的多智能体 AI 问诊 Web 系统（网站 + API），用户输入症状，系统通过分诊 → 专科诊断 → 方案审查 → 随访跟踪的完整 Agent 流水线，输出结构化、可溯源的医疗参考建议。

2. 目标用户及痛点

面向哪些用户：

普通患者（核心用户）：有轻微不适但不确定是否该去医院的用户
基层医疗工作者：需要辅助诊断参考的社区医生
上班族：能及时的久坐提醒、健康数据分析，后面计划接入各家健康手表来获得更多的身体数据来综合分析
在什么场景下使用：

深夜突发轻微不适，不方便立即就医时，先通过 AI 问诊做初步判断
外地旅行时出现不明症状，快速获取分诊建议和科室推荐
慢性病患者在两次复诊之间监测病情变化，获取随访提醒
日常办公室的温馨提醒
当前痛点：

搜索引擎结果混杂广告，难以分辨可靠信息
现有 AI 问诊产品多为商业闭源，回答缺乏证据溯源和审核
患者不知道自己的症状该挂什么科，常挂错号浪费时间和金钱
缺乏开源方案让开发者参与改进，医疗 AI 领域被大公司垄断
3. 价值与意义

**社会价值：MediNexus 致力于弥合医疗信息差，让任何有网络的人都能获得**参考级****的医疗建议。系统采用三路 RAG 知识库（临床病例 + 医学理论 + 前沿论文），所有输出带证据等级标记（A/B/C），由独立的 Review Agent 二次审核，最大程度降低 AI 幻觉带来的误导风险。项目完全开源，任何人都可以审查、改进、部署自己的实例，真正实现"医疗 AI 不应是黑箱"。
**商业价值：**项目可以采用 “Ollama 本地模型默认 + BYO Key” 的策略，用户零成本即可启动。未来可通过企业私有化部署、医院定制化 Skill 插件市场等方向探索可持续模式。
**学习价值：**项目已在作者的github上开源，包含了作者的开发过程和学习文档，为开发多Agent项目提供一定的学习参考。
